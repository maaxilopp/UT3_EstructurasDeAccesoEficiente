## Parte 1

### Object.hashCode()
En la clase Object, el método hashCode() es nativo de la JVM y devuelve un entero asociado a la identidad del objeto en memoria.

En general, dos objetos distintos tendrán códigos hash distintos, aunque no es obligatorio que siempre sea así. Su objetivo principal es dar una representación numérica del objeto para estructuras basadas en hashing.

### Integer.hashCode()
En Integer, hashCode() no usa la identidad del objeto, sino el valor numérico contenido.

Por ejemplo:
- new Integer(5).hashCode() devuelve 5

Esto tiene sentido porque dos objetos Integer con el mismo valor deben considerarse equivalentes desde el punto de vista lógico.

### String.hashCode()
En String, hashCode() se calcula a partir del contenido de la cadena.

Java usa una fórmula basada en los caracteres de la cadena, aproximadamente:

```java
for (int i = 0; i < length(); i++) {
        hash = 31 * hash + charAt(i);
    }
    return hash;
```
## Parte 2
Un HashMap se compone principalmente de:
 - Una matriz (array) de "buckets" (nodos) para almacenar pares clave-valor
 - nodos que almacenan:
      - hash
      - key 
      - value 
      - referencia al siguiente nodo
   

Cuando se inserta una clave:
- se calcula hashCode()
- se transforma en un índice del arreglo
- se guarda el par (key, value) en ese bucket
- si hay colisión, se encadenan nodos en la misma posición


## Parte 3
Para que todo funcione bien:
- Si dos objetos son iguales con equals, entonces tienen que devolver el mismo hashCode.
  - El método equals tiene que cumplir estas reglas:
    - un objeto tiene que ser igual a sí mismo (reflexivo)
    - si A es igual a B, entonces B también tiene que ser igual a A (simétrico)
    - si A es igual a B y B es igual a C, entonces A tiene que ser igual a C (transitivo)
    - no debería cambiar el resultado mientras los objetos no cambien (consistente)
    - si se compara con null, tiene que devolver false
